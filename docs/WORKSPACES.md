# Workspace implementation contract

Existing research DB stays Levr's own workspace (`levr`); no research records are moved or shared. A central catalog in that DB manages users, memberships, invitations, sessions and workspaces. Each new workspace gets a separate SQLite database under a durable `workspaces/` directory next to DATABASE_PATH. No starter competitor data for clients; Creative Inbox exists automatically. Owner can access all workspaces; clients can access only assigned workspace(s). Research routes resolve X-Workspace-Id server-side on every request. Default is Levr for owner, first assigned workspace for client. Invalid/foreign workspace denied with404. Client requests must never fall back to Levr's provider key.

Auth integration: auth(db,options) keeps owner env login and adds client password login, invite acceptance. Return {login,requireAuth,logout,ownerEmail,sessionPayload,registerManagementRoutes}. requireAuth sets req.user={id:null|string,email,role:'owner'|'client'}, req.session. sessionPayload(req) => {user,csrf,workspaces:[{id,name}],defaultWorkspaceId}. /api/session handler parent calls this. registerManagementRoutes(app) registers authenticated management routes BEFORE research workspace middleware (parent app.use('/api',requireAuth) first).

GET /api/workspaces => [{id,name,createdAt}] authorized list. POST /api/workspaces owner-only {name} creates catalog row+returns workspace (research DB created lazily). PATCH /api/workspaces/:id owner-only {name}. GET /api/workspaces/:id/members owner-only => [{id,email,createdAt}]. DELETE /api/workspaces/:id/members/:userId owner-only revokes membership and user sessions. GET /api/workspaces/:id/invites owner-only => [{id,email,expiresAt,acceptedAt,revokedAt}], no token. POST /api/workspaces/:id/invites owner-only {email} => {id,email,token,expiresAt}; cryptographic single-use token only returned once, saved hashed. Existing account invite requires existing password to accept; new accounts set password >=16 chars. Reject inviting owner email. DELETE /api/invites/:id revokes owner-only. POST /auth/accept-invite {token,email,password} authenticates recipient, consumes token transactionally, creates session; returns sessionPayload. No email sending; owner copies invitation URL `${location.origin}/invite#token=${token}`. Fragment never sent to HTTP/access logs. No public signup.

Settings: GET /api/settings/provider => {configured:boolean,storageReady:boolean,source:'workspace'|'environment'|null}; PUT same route {apiKey:string} saves only encrypted per-workspace file outside DB, returns status (never key). DELETE removes workspace key (owner global fallback only applies workspace lev r). SecretVault factory `createSecretVault({directory,masterKey,ownerKey})` => {status(workspaceId),get(workspaceId),set(workspaceId,key),delete(workspaceId)}. masterKey defaults LEVR_SECRET_ENCRYPTION_KEY (>=32 chars), derive AES256 key, AES-GCM with workspaceId AAD. Directory default sibling secrets/ under DATABASE_PATH parent. Atomic writes0600 parent0700. No raw key files or DB fields or fingerprints. Existing owner env SCRAPECREATORS_API_KEY only for lev r; each client must configure its own. No credentials in diagnostics. Browser password input only blank/masked; never localStorage, URL, or returned existing value. Typed credential is cleared immediately after save, never embedded in bundle.

Parent server app handles selecting DB via AsyncLocalStorage DB facade and centralized workspace authorization before ALL existing research endpoints. Catalog/auth routes use original DB directly; no workspace override. Parent may inject vault and workspace directory for tests. Auth options ownerEmail/password/production remain compatible. Client login independent of owner password configuration. Session mutation requires existing CSRF/origin checks. POST accept-invite shares login throttling.

Frontend App uses /api/session workspaces for workspace switcher; api helper includes X-Workspace-Id for research requests. On switch clear detail panels, toasts, all data via key-remount workspace content and disregard stale requests. Owner-only Clients page creates workspaces + invitations + revoke; Client Settings page holds provider secret setting. Client must not see Levr owner email or admin controls. Login editable email, /invite route public invite acceptance.

Recovery: owner POST /api/workspaces/:id/members/:userId/reset creates a one-hour reset invitation. /reset#token=... accepts email and new password via POST /auth/reset-password. Password reset tokens are separate purpose from workspace invitations, cannot grant membership, consume once, and revoke prior client sessions. Existing-account normal invitations still require the current password.
