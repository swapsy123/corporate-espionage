# Live retrieval check for Claude

Investigate the FREE Levr Competitor Analysis app at https://levr-competitor-analysis.onrender.com using the signed-in browser and Render access available to you. The user reports that every Instagram preview is unavailable and that paid ads are missing. The separate ARPRA Railway app is outside this task.

Recent patches in `swapsy123/corporate-espionage` on `main` add strict Meta advertiser Page-ID parsing, live library updates while a manual refresh finishes, paid connection/error guidance, and a manual “Refresh media links” action for one Instagram post. The latest change also recovers brief gateway failures on stored-library reads, shows the failing request's label and HTTP status, and offers “Retry loading library” without restarting scraping. Local tests use synthetic provider/CDN/gateway responses; this is not proof of live retrieval. Render uses manual deployment.

1. Check the free service's running commit against GitHub main. Deploy the latest main if needed and wait for a healthy deployment. Preserve the database, disk, existing credentials and environment settings. Do not reset or recreate the service.
   If the ads page still fails, inspect `/api/items?kind=paid...`, `/api/status` and `/api/competitors` separately in the browser network panel. Record which request fails, its HTTP status and content type, and whether it is an app JSON response or a gateway/HTML response. Check Render's application logs at that timestamp for crashes, restarts, out-of-memory termination or request failures. A successful build/startup log does not establish that subsequent requests are healthy. Do not claim that a hosting gateway response is a ScrapeCreators error without evidence.
2. Open the affected workspace. Check the ScrapeCreators connection status and the latest refresh history. Record the competitor, platforms, status, item counts, warnings and sanitized errors. Do not copy keys, cookies, passwords, webhook URLs or full signed CDN URLs into chat or logs.
3. For paid ads, inspect a confirmed Meta Page connection. Confirm its advertiser name and numeric Page ID against its Ad Library review link. An individual ad's `id` is not a Page ID; advertiser links use `view_all_page_id`. Review should use `country=ALL`, `ad_type=all`, `active_status=all`. Collection intentionally requests ACTIVE ads across ALL countries. Check whether the advertiser actually has active ads; inactive review results do not belong in this active-ad library.
4. Run one manual competitor refresh and wait for completion. Record whether Meta returned no active ads, an actionable provider error, or collected ads. Check whether those records appear on Paid ads with filters cleared. A successful Instagram refresh alone does not prove Meta was connected or collected.
5. For one affected Instagram post, record its ordinary original-post URL and the failed image request's host, HTTP status and request type. Check the app's authenticated `/api/workspaces/.../items/.../image/...` request separately from the direct Instagram CDN fallback. The image relay does not call ScrapeCreators. Do not mistake its 502 response for a whole-site startup failure.
6. In that post's detail panel, click “Refresh media links” once. This intentionally uses that workspace's ScrapeCreators credits for one post. Record the response status and sanitized error, if any; if it succeeds, check the refreshed card image and video or carousel. Distinguish missing/expired provider media, CDN denial or timeout, app authentication failure and unsupported media hosts. Do not claim the images work merely because the new links were saved.
7. Confirm whether the original post itself is available. If one normal competitor refresh renews the recent posts successfully, verify multiple cards. Do not repeatedly refresh all competitors or enable scheduled collection to troubleshoot this.

Return the deployed commit, the affected competitor and confirmed Meta Page ID, the paid-refresh result, one affected original Instagram post link, the relevant HTTP statuses, and the observed cause or remaining uncertainty. If a code change is needed, send those findings back to Codex. Do not delete research, rotate credentials, change subscriptions or modify ARPRA.
